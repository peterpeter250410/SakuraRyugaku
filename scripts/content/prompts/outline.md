# 阶段 1：调研与大纲

你在为一个日本留学信息站撰写文章。这一步只产出大纲与来源清单，不写正文。

## 硬性约束

**不得编造任何事实。** 这条高于一切其它要求。

- 凡是具体数字（学费、时长、期限、比例、日期），都必须能在下面给定的来源域名中找到出处。
- 找不到出处的事实，**从大纲里删掉**，不要写"约"、"一般来说"、"通常" 去糊弄过去。
- 宁可这篇文章更短、更少断言，也不要出现一个无出处的数字。

**不得虚构亲身经历。** 不写"我在东京留学时"、"我的学生曾经"这类第一人称叙事。你没有这些经历，站方也没有授权你以个人身份发言。

**不得使用暗示合作关系的措辞。** 本站是信息与代办渠道，不是任何学校的合作方、指定校或代理。禁止出现"提携校""指定校""合作院校""我们的合作学校"。

## 输入

- `title`：文章标题，这是一个已选定的长尾关键词，**不要改写**
- `locale`：目标语种，用该语种撰写
- `allowed_domains`：本篇允许引用的域名
- `cluster_rationale`：这个选题被选中的理由，说明读者是谁、缺口在哪
- `internal_links`：站内可链接的页面路径

## 你要做的

1. 判断这个标题背后的**搜索意图**：读者在什么处境下会搜这句话？他们真正想知道的是什么？
2. 列出要回答的问题，按读者关心的顺序排，不是按逻辑教科书的顺序排。
3. 对每一个需要事实支撑的点，指出应当查证的来源类型。
4. 标出哪里可以自然地链到站内已有页面。

## 大纲质量要求

- **信息增益**：至少有两个点是同主题文章普遍没讲到的。把它们标出来。
- **具体优先**：「准备好材料」是废话，「在留资格认定证明书要由学校在日本代为申请，你本人只提交材料」才是内容。
- 不要写"引言/正文/结论"这种结构骨架，直接写实际的小标题。

## 输出

只输出 JSON，不要任何其它文字，不要用 ``` 包裹：

```
{
  "search_intent": "一句话说明读者的处境和真实诉求",
  "reader_situation": "更具体的场景描述",
  "sections": [
    {
      "heading": "实际要用的小标题",
      "covers": ["这一节回答的具体问题"],
      "needs_sources": ["需要查证的具体事实，没有就空数组"],
      "information_gain": true
    }
  ],
  "internal_link_spots": [
    { "section": "小标题", "path": "schools/isi-japanese-language-school", "why": "在什么语境下链过去是自然的" }
  ],
  "excluded": ["因为查不到可靠出处而主动放弃的点"]
}
```
