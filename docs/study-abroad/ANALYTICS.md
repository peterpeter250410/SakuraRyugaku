# 日本留学中介平台 — 数据分析与指标体系方案

> 文档版本：v1.0
> 更新日期：2026-07-16
> 阅读对象：开发团队内部
> 目的：为「项目是否值得继续投入」提供数据依据（市场验证核心）

---

## 1. 分析目标

本阶段是**市场验证 / 网络市场调研**。数据分析要回答三个问题：

1. **有没有量？** — SEO/投放能带来多少流量（UV/PV/来源）。
2. **转不转化？** — 落地页能把多少流量转化为「有实际意向的学生资料」。
3. **值不值得继续？** — 综合流量、转化、线索质量与成本，判断项目去留。

---

## 2. 数据采集工具链（三位一体）

| 工具 | 职责 | 覆盖 |
|------|------|------|
| **GA4**（Google Analytics 4） | 流量、来源、用户行为、转化事件、漏斗 | 全站行为分析 |
| **Google Search Console** | 自然搜索展现/点击/排名/收录/CWV | SEO 侧 |
| **自建埋点**（数据库落库） | 访问、来源、转化线索**自主留存**，不受第三方限制 | 可控、可归因、可导出 |

> 三者互补：GA4 看行为漏斗，Search Console 看 SEO 效果，自建埋点保证**数据主权**与线索可追溯（尤其转化线索必须自建落库，不能只靠 GA4）。

---

## 3. 指标体系

### 3.1 流量指标（有没有量）

| 指标 | 定义 | 来源 |
|------|------|------|
| PV | 页面浏览量 | GA4 / 自建 |
| UV | 独立访客数 | GA4 / 自建 |
| 会话数 | Sessions | GA4 |
| 新访客比例 | 新用户 / 总用户 | GA4 |
| 流量来源构成 | 自然/直接/推荐/社媒/投放 | GA4 + UTM |
| 自然搜索流量 | Organic Search 占比 | GA4 + Search Console |
| 地域/语言分布 | 访客国家、语言 | GA4 / 自建 |
| 设备分布 | PC vs H5（移动） | GA4 / 自建 |

### 3.2 参与/行为指标

| 指标 | 定义 |
|------|------|
| 平均停留时长 | 页面/会话停留 |
| 跳出率 / 参与率 | 单页离开 / 有效互动 |
| 落地页滚动深度 | 用户看到落地页多深（卖点/表单是否被看到） |
| 页面加载性能 | LCP/CLS/INP（影响体验与转化） |

### 3.3 转化指标（核心，判断项目关键）

| 指标 | 定义 | 说明 |
|------|------|------|
| 表单曝光数 | 意向表单进入视口次数 | 漏斗起点 |
| 开始填写数 | 用户开始输入表单 | 意向强度 |
| **提交成功数（线索数）** | 成功提交意向信息的数量 | **核心产出** |
| **转化率** | 线索数 / UV | **核心判据** |
| 有效线索数 | 联系方式真实、意向明确的线索 | 质量维度 |
| 线索来源构成 | 各渠道/关键词贡献的线索 | 归因 |
| 分终端转化率 | PC vs H5 转化差异 | 优化方向 |

### 3.4 SEO 指标（Search Console）

| 指标 | 定义 |
|------|------|
| 收录页面数 | 被索引的页面 |
| 展现次数 | 搜索结果中出现次数 |
| 点击次数 | 自然搜索点击 |
| CTR | 点击 / 展现 |
| 平均排名 | 关键词平均位置 |
| 覆盖关键词数 | 带来展现的词数 |

---

## 4. 转化漏斗定义

```
搜索展现(SC) → 点击进站(SC/GA4) → 落地页访问(GA4/自建)
   → 表单曝光 → 开始填写 → 提交成功(线索) → 有效线索(人工/规则核验)
```

每一步都埋点，计算各环节转化率，定位流失点（如「访问多但表单曝光少」=首屏引导差；「开始填写多但提交少」=表单太长/字段有阻力）。

## 5. 埋点设计

### 5.1 GA4 事件（M-06/09）

| 事件名 | 触发时机 | 关键参数 |
|--------|---------|---------|
| `page_view` | 页面加载 | page_location, language, device |
| `lp_view` | 落地页加载 | lp_variant(A/B) |
| `form_impression` | 表单进入视口 | form_id |
| `form_start` | 首次输入表单 | form_id |
| `form_submit` | 提交成功 | form_id, has_contact, has_intent |
| `cta_click` | 点击 CTA/咨询 | cta_position |
| `scroll_depth` | 滚动 25/50/75/100% | percent |

- `form_submit` 标记为 GA4 **转化（Conversion / Key Event）**。
- UTM 参数（M-10）随事件透传，实现渠道归因。

### 5.2 自建埋点（M-08，落库）

> 目的：转化线索与访问数据**自主留存**，可离线分析、可导出、可长期追溯，不受第三方采样/合规限制。

**表：`{prefix}sa_analytics_events`（访问/行为事件）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| event_type | VARCHAR(64) | pageview / lp_view / form_impression / form_start / form_submit / cta_click |
| session_key | CHAR(36) | 匿名会话标识（cookie/localStorage 生成） |
| page_url | VARCHAR(255) | 页面 URL |
| referrer | VARCHAR(255) | 来源 |
| utm_source | VARCHAR(64) | 渠道来源 |
| utm_medium | VARCHAR(64) | 媒介 |
| utm_campaign | VARCHAR(64) | 活动 |
| device | VARCHAR(16) | pc / h5 |
| locale | VARCHAR(16) | 语种 |
| country | VARCHAR(64) | 国家（可由 IP 粗定位，注意隐私） |
| ip_hash | CHAR(64) | IP 哈希（不存明文，合规） |
| meta | JSON | 附加参数（lp_variant、scroll 等） |
| created_at | DATETIME | 时间 |

索引：`INDEX(event_type, created_at)`，`INDEX(session_key)`，`INDEX(utm_source)`。

**表：`{prefix}sa_leads`（意向线索，核心产出）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| session_key | CHAR(36) | 关联会话（做端到端归因） |
| name | VARCHAR(191) | 姓名 |
| contact_type | VARCHAR(16) | email / phone / line / wechat / whatsapp |
| contact_value | VARCHAR(191) | 联系方式（敏感，见合规） |
| budget_min | INT UNSIGNED | 预算下限 |
| budget_max | INT UNSIGNED | 预算上限 |
| intended_major | VARCHAR(191) | 意向专业 |
| extra | JSON | 其他意向信息（学历/时间/地区等） |
| lp_variant | VARCHAR(32) | 来源落地页版本 |
| utm_source | VARCHAR(64) | 渠道 |
| utm_medium | VARCHAR(64) | 媒介 |
| utm_campaign | VARCHAR(64) | 活动 |
| lead_status | ENUM('new','valid','invalid','contacted','converted') | 线索状态 |
| quality_note | VARCHAR(255) | 质量备注 |
| created_at | DATETIME | 提交时间 |

索引：`INDEX(lead_status)`，`INDEX(utm_source)`，`INDEX(created_at)`。

> **合规提醒**：`sa_leads` 含个人联系方式，属敏感数据；表单页需隐私同意，联系方式建议加密/访问受控（对齐 `SECURITY-DESIGN.md`）。IP 存哈希不存明文。

## 6. 后台数据看板（M-11）

管理后台提供可视化看板，避免每次去 GA4 拼数据：

- 核心卡片：UV、PV、线索数、转化率（可选时间范围）
- 趋势图：UV/线索/转化率随时间变化
- 来源构成：渠道/关键词/UTM 贡献的流量与线索
- 终端对比：PC vs H5 的流量与转化
- 落地页版本对比：A/B 版本转化率（配合 L-10）
- 漏斗图：曝光→填写→提交各环节转化

## 7. 阶段性分析报告模板（M-12）

> 阶段末产出报告，直接服务「项目去留」决策。

```
# 市场验证阶段数据报告（周期：YYYY-MM-DD ~ YYYY-MM-DD）

## 一、流量概览
- UV / PV / 会话数 / 新访客比例
- 来源构成（自然/直接/推荐/投放）

## 二、SEO 效果
- 收录页面数 / 展现 / 点击 / CTR / 平均排名

- 技术健康（CWV / 抓取错误）

## 三、转化分析
- 漏斗各环节转化率
- 线索总数 / 有效线索数 / 转化率
- 分渠道 / 分关键词 / 分终端 / 分落地页版本转化对比

## 四、线索质量
- 有效/无效线索占比与原因
- 意向分布（预算区间 / 专业分布）

## 五、成本与效率（如有投放）
- 单条有效线索成本趋势

## 六、结论与建议
- 是否达到验证判据（对照阈值）
- 项目去留建议：继续投入 / 调整方向 / 暂停
- 若继续：下一阶段优化重点与 App 规划触发条件
```

## 8. 验证判据与决策阈值（示例）

> 具体阈值应结合行业基准与实际投入设定，以下为**决策框架示例**（占位，需按市场调研校准）：

| 维度 | 观察指标 | 示例阈值（需校准） | 决策含义 |
|------|---------|-------------------|---------|
| 流量 | 阶段 UV | 达到 X | 低于则 SEO/选题需调整 |
| 转化 | 落地页转化率 | ≥ Y% | 达标说明需求真实、落地页有效 |
| 线索 | 有效线索数 | ≥ Z 条 | 足以支撑后续业务跟进 |
| 质量 | 有效线索占比 | ≥ W% | 反映流量精准度 |
| 成本 | 单有效线索成本 | ≤ C | 商业可行性 |

**决策逻辑（示例）**：
- 流量达标 + 转化达标 + 线索足量优质 → **继续投入**（启动更完整开发 / App 规划）。
- 流量达标但转化差 → 优化落地页/表单，再验证。
- 流量不足 → 优化 SEO/内容/关键词，或评估市场需求。
- 多轮验证仍不达标 → **暂停/转向**，避免持续沉没成本。

> 阈值 X/Y/Z/W/C 待商务与市场目标确定后填入，本文档提供决策框架。

## 9. 数据合规与隐私

- 采集前隐私同意（同 `SECURITY-DESIGN.md`）。
- IP 不存明文（哈希）；GA4 启用 IP 匿名化。
- 线索联系方式受控访问 / 加密。
- Cookie/追踪告知与（按地区）同意管理。
- 隐私政策页说明数据用途与留存。
