| 域名 | 角色 | 状态 | 面向市场 |

| `sakuraryugaku.jp` | 日本市场主域（就绪后启用） | 待代理注册 | 日本本地 |

日本本地市场后续再补 `.jp`，两域以 hreflang 互指。

**待明确项**：
- 服务器落地位置：境外/港台可免备案快速上线；若后续用大陆服务器主打百度流量则需 ICP 备案。

## 1. 项目概述

### 1.1 项目背景

本项目是一个**全新独立**的日本留学中介平台（与仓库中已有的 EIKOU 会展站原型无关，仅复用 WordPress 技术基础）。平台面向有意赴日留学的学生，提供从信息咨询、院校智能匹配、选校决策到申请材料提交的一站式在线服务。

### 1.2 核心价值主张

- **降低咨询门槛**：学生填写基础信息即可获得系统自动匹配的院校推荐，无需先付费面谈。
- **提升匹配效率**：后台预配置院校库 + 自动匹配算法，减少人工初筛工作量。
- **规范材料管理**：学生在线提交敏感申请材料，加密入库，集中管理，避免线下材料丢失/泄露。
- **多语言覆盖**：架构上支持远超日/中/英三语的多语种扩展，服务多国生源。

### 1.3 项目目标

| 目标类别 | 具体目标 |
|---------|---------|
| 业务目标 | 支持学生在线咨询、预约、自动匹配院校、选校、提交资料入库 |
| 效率目标 | 自动匹配替代人工初筛，缩短从咨询到选校的周期 |
| 数据目标 | 学生敏感材料加密存储，形成结构化的学生-院校数据资产 |
| 扩展目标 | 多语言架构预留，后续可快速接入更多语种 |

## 2. 核心业务流程

```
┌──────────┐   ┌──────────┐   ┌──────────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 1.注册   │──▶│ 2.提交   │──▶│ 3.系统自动   │──▶│ 4.推送   │──▶│ 5.学生   │──▶│ 6.提交   │
│   登录   │   │  基础信息│   │   匹配院校   │   │  推荐结果│   │   选校   │   │  申请资料│
└──────────┘   └──────────┘   └──────────────┘   └──────────┘   └──────────┘   └──────────┘
                                      │                                              │
                                      ▼                                              ▼
                             ┌─────────────────┐                          ┌─────────────────┐
                             │ 后台预配置院校库 │                          │  资料加密入库    │
                             │ (匹配规则/条件)  │                          │  (顾问后台管理)  │
                             └─────────────────┘                          └─────────────────┘
```

### 2.1 流程详细说明

1. **注册登录**：学生注册账号（邮箱/手机），登录后进入个人中心。
2. **提交基础信息**：填写匹配所需的基础信息（当前暂定核心匹配条件为**预算**和**意向专业**，其余字段作为辅助信息与后续扩展）。
3. **系统自动匹配**：系统依据学生条件，在后台预配置的院校库中按匹配规则筛选并排序，生成推荐院校列表。
4. **推送推荐结果**：匹配结果推送到学生个人中心（并可通过邮件/站内通知提醒）。
5. **学生选校**：学生查看推荐院校详情，选定一所或多所目标院校。
6. **提交申请资料**：学生针对所选院校上传申请材料（护照、成绩单、证件照等），材料**加密存储**，进入顾问后台管理流程。

> 注：匹配条件字段目前无法完全细化，MVP 阶段以「预算 + 专业」为核心匹配维度，其他字段（学历、语言能力、地区、入学时间等）作为可扩展权重项预留。详见 `MATCHING-ALGORITHM.md`。

## 3. 角色与权限

| 角色 | 说明 | 主要权限 |
|-----|------|---------|
| 游客 | 未登录访客 | 浏览官网内容、查看院校公开信息、注册 |
| 学生（Student） | 注册用户 | 提交基础信息、查看匹配结果、选校、上传资料、查看进度、站内沟通 |
| 顾问（Advisor） | 留学顾问 | 查看**自己负责**的学生资料、审核材料、跟进沟通、调整推荐 |
| 管理员（Admin） | 平台管理员 | 院校库管理、匹配规则配置、全量学生管理、顾问分配、系统设置 |

> 权限分级要求：顾问只能查看自己负责的学生资料，避免信息越权。详见 `SECURITY-DESIGN.md`。

## 6. 技术选型概览

| 层次 | 选型 | 说明 |
|-----|------|------|
| CMS 底座 | WordPress (PHP 7.4+) | 沿用仓库现有基础，内容易维护 |
| 内容展示 | 自定义主题 | 官网页 + 学生个人中心前端 |
| 业务逻辑 | 自定义插件 | 匹配引擎、资料管理、权限控制等业务代码集中于插件 |
| 数据存储 | MySQL（WP 自定义表 + CPT） | 院校/匹配/资料等用自定义表；内容类用 CPT |
| 多语言 | 架构预留（详见 I18N-DESIGN） | 复用仓库现有 i18n 脚本思路，扩展多语种 |
| 文件加密 | 服务端加密 + 受保护目录 | 敏感附件加密存储、防盗链 |
| 部署 | 宝塔面板 + 现有 deploy 脚本 | 沿用仓库 scripts/ |

> 技术架构详细设计见 `TECH-ARCHITECTURE.md`。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|-----|------|------|
| 匹配条件难以细化 | 匹配结果不精准 | MVP 先用预算+专业，算法设计为可扩展权重模型，后续加字段不改架构 |
| 敏感个人信息泄露 | 合规/法律风险 | 附件加密存储、后台权限分级、隐私同意书、访问日志 |
| 多语种范围不确定 | 返工风险 | 架构层面语种可配置，翻译内容与代码解耦，语种后补不影响主体 |
| WordPress 承载复杂业务 | 性能/可维护性 | 业务逻辑集中在自定义插件，自定义表隔离，避免滥用 postmeta |
| 院校库维护成本 | 数据陈旧 | 后台批量导入 + 字段规范化，预留后续 API 对接接口 |
