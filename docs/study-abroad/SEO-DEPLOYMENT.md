# 日本留学中介平台 — 白帽 SEO 部署与测试方案

> 文档版本：v1.0
> 更新日期：2026-07-16
> 阅读对象：开发团队内部
> 适用阶段：市场验证阶段（配合落地页 + 数据分析判断项目去留）

---

## 1. 目标与原则

### 1.1 目标

- 用**白帽 SEO**（合规、可持续）为落地页与官网带来自然搜索流量。
- 覆盖**多目标市场**：中国（百度）、国际（Google）、日本本地（Google）。
- 让搜索引擎正确收录、理解、排名本站页面，为「意向信息表单」引流。
- 为项目去留决策提供可归因的自然流量数据。

### 1.2 白帽原则（严守，杜绝黑帽）

| 做（White Hat） | 不做（Black Hat，禁止） |
|-----------------|------------------------|
| 优质原创内容、真实院校信息 | 关键词堆砌、隐藏文字 |
| 语义化结构、正确标签 | 门页（doorway）、桥页 |
| 自然获取的外链、合作互链 | 买链接、链接农场、PBN |
| 提升真实用户体验与速度 | Cloaking（对搜索引擎与用户显示不同内容）|
| 合规结构化数据 | 虚假 Schema、垃圾评论刷量 |

> 黑帽手段短期见效但会被惩罚/封站，与「长期验证真实市场」目标相悖，本方案一律不采用。

### 1.3 域名方案（已定）

**品牌域名：`sakuraryugaku`**（桜 + 留学，日式意象 + 核心关键词，SEO 与记忆度俱佳）。

| 域名 | 角色 | 状态 | 面向市场 |
|------|------|------|---------|
| **sakuraryugaku.com** | **当前主域**（先行上线验证） | 待注册 | 中国 / 国际（.com 通用信任度高、免备案可快速上线） |
| **sakuraryugaku.jp** | 日本市场主域（就绪后启用） | 待代理注册 | 日本本地（.jp 本地信任、利于日本 Google SEO） |

**决策依据**：市场验证阶段核心是**快速上线跑数据**。`.com` 无实名/备案要求，可立即上线，
且中日国际市场通用；相比 `.cn`，省下的域名费（约 42 元）远小于备案耗时带来的验证延迟成本，
故主域采用 `.com`。日本本地市场后续再补 `.jp`。

> 备注：曾评估 `.cn`（更便宜），但其需实名认证 + 大陆服务器须 ICP 备案，会拖慢验证节奏，故不采用。

#### .com 注册说明

`.com` 由通用注册商（GoDaddy、Namecheap、阿里云/腾讯云国际、Cloudflare 等）自由注册，
**无本地资质要求，无需备案**（除非落地大陆服务器）。

> 提醒：`sakuraryugaku.com` 是否已被注册需在注册商查询 whois 确认后再注册。

#### 服务器与上线（免备案，快速上线）

- `.com` + **境外 / 港台服务器** → 免 ICP 备案，可快速上线跑市场验证。
- 若后续主打大陆百度流量且用大陆服务器，则需办理 ICP 备案（届时再评估）。

#### .jp 注册说明（日本主域，后补）

`.jp` 由 **JPRS** 管理，有**日本本地存在要求**：
- **汎用 .jp（`sakuraryugaku.jp`）**：注册者需具备日本国内联系地址（个人或法人）。
- 暂无日本实体时，可用注册商的「日本地址代理 / JP Local Presence」服务注册。

#### 域名就绪后的配套（无需改代码）

- 主题已内置多语言语种路由（`/zh` `/en` 前缀）与 hreflang，域名切换即生效。
- `.com` 主域承接中文/英文与国际流量；`.jp` 就绪后以日语为默认语种承接日本市场，两域通过 hreflang 互指，避免重复内容。
- 中国市场提交**百度搜索资源平台**；日本/国际提交 **Google Search Console**；各域独立验证并提交 sitemap。

## 2. 多市场 SEO 策略

| 市场 | 搜索引擎 | 语言 | 收录/站长工具 | 承载域名 | 备注 |
|------|---------|------|--------------|---------|------|
| 中国 | 百度为主 | 简体中文 | 百度搜索资源平台 | sakuraryugaku.com（/zh） | 主域；大陆百度收录若需最佳效果可后续配大陆服务器+备案 |
| 国际 | Google | 多语言 | Google Search Console | sakuraryugaku.com | 主战场，多语种 hreflang |
| 日本本地 | Google 为主 | 日语 | Google Search Console | sakuraryugaku.jp（就绪后） | 日本 Google 份额高，.jp 本地信任度高 |

**语言与页面策略**（配合 `I18N-DESIGN.md`）：
- 每个目标语种有独立可索引 URL（语种前缀，如 `/zh` `/en`，日语为默认）。
- 使用 `hreflang` 标注各语种版本互为替代，避免重复内容问题。
- 每语种页面的 title/description/关键词按该语言市场独立优化，而非机翻堆砌。

## 3. 关键词策略

### 3.1 关键词分层

| 层级 | 示例（按市场语言化） | 落地页面 |
|------|---------------------|---------|
| 核心词（高竞争） | 日本留学、留学日本、Study in Japan、日本留学 エージェント | 首页 / 主落地页 |
| 意向词（转化高） | 日本语言学校申请、日本读研中介、日本大学出愿 サポート | 服务/落地页 |
| 长尾词（易排名） | 高中毕业去日本留学费用、文科生日本读研专业、N2 能上什么大学 | FAQ/资讯/院校页 |
| 品牌词 | 品牌名 + 留学 | 首页 |

### 3.2 关键词落地映射（M-04）

- 建立「关键词 → 目标页面 → 意图」映射表，避免多页争抢同一词（关键词自我竞争）。
- 每个页面聚焦 1 个主关键词 + 若干相关长尾。
- 长尾词用 FAQ / 资讯博客承接（利于收录与转化）。

> 具体关键词表随市场调研补充；本阶段先覆盖核心 + 高转化意向词。

## 4. 站内 SEO（On-Page）实施清单

### 4.1 页面级

- [ ] 唯一且描述性的 `<title>`（含主关键词，长度适中）
- [ ] `meta description`（吸引点击，含关键词与价值主张）
- [ ] 唯一 `H1`，合理的 `H2/H3` 层级
- [ ] `canonical` 指向规范 URL，避免重复内容
- [ ] 图片 `alt`、语义化 HTML5 标签
- [ ] 内链结构清晰（落地页/院校/FAQ 互链）
- [ ] URL 简洁、含关键词、可读（避免长参数）

### 4.2 站点级

- [ ] `robots.txt` 正确（放行可索引页，屏蔽后台/隐私页/参数页）
- [ ] `sitemap.xml` 自动生成并提交（含多语种页）
- [ ] `hreflang` 多语种标注
- [ ] 结构化数据 JSON-LD：`Organization`、`FAQPage`、`BreadcrumbList`、（可选）`Course`
- [ ] 404 页面友好、返回正确状态码
- [ ] HTTPS 全站、HTTP→HTTPS 301
- [ ] 规范化 www/非 www、尾斜杠一致

### 4.3 技术 SEO 与性能（Core Web Vitals，M-05）

| 指标 | 目标 | 手段 |
|------|------|------|
| LCP（最大内容绘制） | < 2.5s | 首屏图片优化/预加载、关键 CSS 内联、CDN |
| CLS（布局偏移） | < 0.1 | 图片/媒体指定尺寸、字体 swap |
| INP（交互响应） | < 200ms | 减少主线程阻塞、延迟非关键 JS |
| 移动优先 | — | H5 响应式、可点击区域足够大 |
| 缓存 | — | 页面缓存、浏览器缓存、静态资源版本化 |

> 落地页性能直接影响 SEO 排名与转化，是本阶段重点。

## 5. 内容 SEO

- **落地页**：围绕核心/意向关键词，价值主张清晰，结构化，转化导向。
- **FAQ 页**：承接长尾问题词（费用、条件、流程、专业选择），可上 FAQ Schema。
- **资讯/博客**（P1）：留学政策、院校介绍、申请攻略，持续产出提升权重与长尾覆盖。
- **院校详情页**：真实结构化信息，天然长尾词入口。
- 内容原创、对用户有用，避免机翻低质与重复。

---

## 6. 站外 SEO（White Hat）

- 真实合作机构/院校的自然互链。
- 高质量目录/行业站点收录。
- 社媒/内容平台引流（间接助力）。
- **不做**买链接、链接农场、刷外链。

## 7. 部署步骤

> 域名与服务器暂未最终确定，以下为「环境就绪后」的标准部署流程。

```
阶段 A：上线前
  1. 站点可访问、HTTPS 生效、robots/sitemap 就位
  2. 各语种页面可索引、hreflang 正确
  3. 结构化数据校验通过（Rich Results Test）
  4. Core Web Vitals 达标（PageSpeed Insights / Lighthouse）
  5. 埋点就位（GA4 / Search Console 验证码 / 自建埋点，见 ANALYTICS.md）

阶段 B：上线收录
  6. Google Search Console 验证站点、提交 sitemap
  7. 百度搜索资源平台验证、提交（面向中国市场时；需备案）
  8. 主动提交核心 URL 加速收录
  9. 内链完善，确保爬虫可达全部重要页

阶段 C：监控与迭代
  10. 监控收录量、关键词展现/点击、排名
  11. 监控 Core Web Vitals 与抓取错误
  12. 按数据迭代 title/description/内容/内链
```

## 8. 初步效果检查（本阶段核心）

> 目的：SEO 上线后做**初步效果检查**，配合数据分析判断项目潜力。

### 8.1 检查项

| 类别 | 检查项 | 工具 |
|------|--------|------|
| 收录 | 页面是否被收录、收录数量 | Search Console / `site:` 查询 |
| 展现 | 关键词展现次数、覆盖词 | Search Console |
| 点击 | 自然搜索点击量、CTR | Search Console |
| 排名 | 核心/意向词排名位置 | Search Console / 排名工具 |
| 流量 | 自然搜索 UV/PV、来源国家/语言 | GA4 + 自建埋点 |
| 转化 | 自然流量的意向表单提交率 | GA4 转化事件 + 自建埋点 |
| 技术 | 抓取错误、CWV、移动可用性 | Search Console / PSI |

### 8.2 效果检查节奏

- **上线即时**：收录提交、埋点验证、CWV 基线。
- **周度**：收录量、展现、点击、CTR、转化趋势。
- **阶段末**：汇总形成报告（见 `ANALYTICS.md` 报告模板），支撑去留决策。
