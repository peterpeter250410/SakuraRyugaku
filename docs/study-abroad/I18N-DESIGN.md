# 日本留学中介平台 — 多语言架构设计

> 文档版本：v1.0
> 更新日期：2026-07-16
> 阅读对象：开发团队内部

---

## 1. 设计目标

- 目标用户为多国生源，语种**远超日/中/英**，且**后续会陆续补充**具体语种。
- 因此多语言必须**架构先行、语种可配置**：新增语种只需加配置与译文，**不改代码结构**。
- 区分两类可翻译内容：
  1. **界面文案（UI 字符串）**：走 gettext 国际化。
  2. **动态内容（院校信息等）**：走内容多语言字段（`*_i18n` JSON）。

---

## 2. 借鉴现有方案并扩展

仓库现有 EIKOU 站采用 **主题 gettext（.mo）+ 轻量语言路由（URL 前缀 /zh /en）**，不使用 Polylang（见 `docs/i18n-deploy.md`）。本项目**沿用同一思路并扩展为多语种**：

| 现有（三语固定） | 本项目（多语种可扩展） |
|-----------------|----------------------|
| 硬编码 `/zh` `/en` 前缀分支 | **语种注册表驱动**，前缀由配置生成 |
| 每语言一个 .mo | 每语言一个 .mo，语种列表可增删 |
| DeepL 固定源=日文 | 源语言可配置，翻译流程按语种批量 |

---

## 3. 语种注册表（核心）

用一份**可配置语种表**驱动全站多语言，而非硬编码：

```php
// 概念结构（配置驱动，实际可存 option 或配置文件）
$locales = [
    'ja'    => [ 'label' => '日本語',   'url_prefix' => '',    'wp_locale' => 'ja',    'dir' => 'ltr', 'default' => true ],
    'zh_CN' => [ 'label' => '中文',      'url_prefix' => 'zh',  'wp_locale' => 'zh_CN', 'dir' => 'ltr' ],
    'en_US' => [ 'label' => 'English',   'url_prefix' => 'en',  'wp_locale' => 'en_US', 'dir' => 'ltr' ],
    // 后续补充语种：只在此追加，无需改逻辑
    // 'ko_KR' => [ 'label' => '한국어',  'url_prefix' => 'ko', 'wp_locale' => 'ko_KR', 'dir' => 'ltr' ],
    // 'vi'    => [ 'label' => 'Tiếng Việt','url_prefix' => 'vi','wp_locale' => 'vi',   'dir' => 'ltr' ],
    // 'ar'    => [ 'label' => 'العربية', 'url_prefix' => 'ar', 'wp_locale' => 'ar',   'dir' => 'rtl' ], // 含 RTL 支持
];
```

**要点**：
- 语言路由、切换器 UI、`home_url`/链接前缀、`.mo` 加载**全部遍历此表生成**，新增语种自动生效。
- 支持 `dir`（ltr/rtl），为阿拉伯语等 RTL 语种预留。
- `default` 标记默认语种（无前缀）。

---

## 4. 语言路由

复用现有轻量路由思路，改为注册表驱动：

```
请求 URL → 匹配语种注册表中的 url_prefix
   命中 → 设置当前 locale，剥离前缀，交 WP 正常路由
   未命中 → 使用默认语种
挂载过滤器：
   - locale / determine_locale → 返回当前语种 wp_locale
   - load_textdomain          → 加载对应 .mo（主题 + 插件）
   - home_url / *_link        → 自动加当前语种前缀
   - 次级语种禁用 redirect_canonical（避免前缀剥离后重定向死循环）
   - 输出 <html lang> 与 dir 属性
```

## 5. 两类内容的多语言处理

### 5.1 界面文案（UI 字符串）→ gettext

- 主题与插件所有 UI 字符串用 `__()/_e()/esc_html__()` 包裹，指定 text domain。
  - 主题 domain：`sa-theme`
  - 插件 domain：`sa-core`
- 提取 `.pot` → 各语种 `.po` → 编译 `.mo`。
- 复用/参考仓库 `scripts/i18n-extract.php`、`i18n-translate-po.php`、`i18n-make-translations.sh` 工具链，扩展为按语种循环处理。

### 5.2 动态内容（院校/专业/资讯）→ i18n 字段

- 结构化内容表（`sa_schools`/`sa_programs`）用 `*_i18n` JSON 字段存多语种：
  ```json
  { "ja": "早稲田大学", "zh_CN": "早稻田大学", "en_US": "Waseda University" }
  ```
- 读取时按当前 locale 取值，**缺失回退默认语种**。
- 新增语种 = JSON 加一个键，无需改表结构。
- CPT 展示内容（富文本介绍）多语言方案：
  - 方案 A（推荐 MVP）：`*_i18n` JSON / postmeta 分语种存字段。
  - 方案 B（内容量大时）：按语种维护译文，后台提供翻译编辑界面。

---

## 6. 语言切换器 UI

- 由语种注册表动态渲染下拉/列表。
- 切换时跳转到**当前页面对应语种的 URL**（保持上下文，不回首页）。
- 移动端适配。
- 显示各语种 `label`（本地化名称，如「日本語 / 中文 / English / 한국어」）。

---

## 7. 用户语言偏好

- 学生 `sa_student_profiles.preferred_locale` 记录首选语种。
- 登录后按偏好自动切换；未登录可按浏览器 `Accept-Language` 猜测默认语种（P2）。
- 通知/邮件按学生偏好语种发送（模板多语种化）。

---

## 8. 翻译工作流（多语种扩展）

```
1. 开发用默认源语言（如日文或英文）编写 UI 字符串（gettext 包裹）
2. 提取 .pot
3. 对语种注册表中每个语种：
     - 生成/更新该语种 .po
     - 机器翻译（DeepL/其它，源语言可配置）填充未译条目
     - 保留已人工校对条目
     - 编译 .mo
4. 动态内容：后台录入时按语种填写 *_i18n，或提供翻译辅助
```

- 新增语种：注册表加一行 → 跑翻译脚本生成该语种 .po/.mo → 动态内容补该语种键。

---

## 9. 注意事项（承接现有经验）

- **翻译文件（.po/.mo）管理**：可选择纳入版本控制或仅存服务器；部署脚本需 `--exclude` 保护避免误删（参考现有 `server-deploy.sh` 做法）。
- **动态录入内容不走 .mo**：院校/资讯等用户数据用 `*_i18n` 字段，不依赖 gettext。
- **跨语言不变的信息**（公司名、邮箱、电话）可保留原值。
- **RTL 语种**：预留 `dir` 属性与 RTL 样式（如后续接入阿拉伯语）。
- **数字/货币/日期**：学费（日元）、日期按 locale 格式化展示。

---

## 10. 验收要点

- 新增一个语种，仅通过「注册表加行 + 跑翻译脚本 + 补内容键」即可上线，**不改业务代码**。
- 语言切换保持页面上下文。
- UI 与动态内容均按当前语种正确显示，缺失有回退。
- 通知/邮件按用户偏好语种发送。

---

_多语言架构以「配置驱动、代码不随语种增长而改」为核心原则。_
