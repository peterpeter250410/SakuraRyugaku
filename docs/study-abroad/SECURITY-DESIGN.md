# 日本留学中介平台 — 安全与合规设计

> 文档版本：v1.0
> 更新日期：2026-07-16
> 阅读对象：开发团队内部

---

## 1. 安全目标

平台处理学生**敏感个人信息**（护照、成绩单、证件照等）。安全设计围绕三条主线：

1. **机密性**：敏感附件加密存储，防止泄露与直连盗取。
2. **访问控制**：权限分级，顾问只能访问被分配的学生数据，杜绝越权。
3. **合规**：满足个人信息保护要求（信息收集同意、数据删除权、访问留痕）。

---

## 2. 附件加密存储（核心）

### 2.1 存储位置

- 上传文件**不放入** Web 可直接访问的 `wp-content/uploads` 公开路径。
- 存放于受保护目录，例如 `wp-content/uploads/sa-secure/`，并通过以下手段禁止直连：
  - Apache：目录内 `.htaccess` `Deny from all` / `Require all denied`。
  - Nginx：`location` 规则拒绝直接访问该目录。
  - 文件名使用随机化标识（非可猜测的原始名）。

### 2.2 加密方案

```
上传流程：
  1. 校验文件类型（白名单）与大小
  2. 生成随机 IV（每文件唯一）
  3. 用 AES-256-GCM（或 CBC+HMAC）加密文件内容
  4. 密文写入受保护目录
  5. 记录：stored_path / enc_iv / key_ref / checksum(明文SHA-256) / enc_algo

下载流程：
  1. 鉴权（本人 / 被分配顾问 / 管理员）
  2. 读取密文 + IV，用密钥解密
  3. 校验 checksum（完整性）
  4. 流式输出，设置正确 Content-Type / Content-Disposition
  5. 记录审计日志（download_doc）
```

### 2.3 密钥管理

- 加密密钥**不与文件同目录、不入数据库明文**。
- 密钥来源建议：独立于站点数据库的密钥文件（受限权限）或环境变量 / 密钥管理服务。
- 数据库仅存 `key_ref`（密钥标识/版本），支持密钥轮换。
- 密钥文件权限最小化（仅 Web 用户可读），排除出版本控制与备份公开路径。

### 2.4 完整性

- 存明文 `SHA-256 checksum`，解密后校验，防止密文被篡改导致的静默损坏。
- 采用 GCM 等 AEAD 模式时，附带认证标签防篡改。

## 3. 访问控制与权限分级

### 3.1 角色能力（Capabilities）

| 角色 | 能力范围 |
|------|---------|
| `sa_student` | 仅本人：档案、匹配结果、选校、资料、消息 |
| `sa_advisor` | 仅**被分配**学生的数据；审核资料、沟通 |
| `sa_admin` | 全量数据、院校库、匹配规则、分配、系统设置 |

### 3.2 越权防护（Access Guard）

- 所有涉及学生数据的读写，**在数据访问前统一鉴权**：
  ```
  学生请求 → 校验 目标数据.user_id == 当前登录用户
  顾问请求 → 校验 sa_assignments 中 (advisor=当前用户, student=目标) 存在且 active
  管理员   → 放行（仍记日志）
  ```
- 禁止仅靠前端隐藏；后端强制校验。
- 资料下载端点（PHP）必须鉴权后才解密输出，不暴露物理路径。

### 3.3 接口安全

- 前后端交互走 **REST API + Nonce**，校验来源与权限。
- 避免无鉴权 `admin-ajax` 端点。
- 所有 `$wpdb` 查询使用 `prepare()` 预处理，防 SQL 注入。
- 输出统一转义（`esc_html` / `esc_attr` / `esc_url`），防 XSS。
- 表单提交 CSRF 防护（WP Nonce）。

## 4. 合规（个人信息保护）

### 4.1 信息收集同意

- 采集基础信息 / 上传资料前，**必须勾选同意隐私政策**。
- 记录同意状态与时间（`consent_privacy` / `consent_at`）。
- 提供隐私政策页面，说明收集范围、用途、存储期限、第三方共享情况。

### 4.2 数据主体权利

- **访问权**：学生可查看自己提交的全部信息。
- **删除权**：学生可申请注销账号并删除个人数据（含加密附件安全删除）。
- **更正权**：学生可修改基础信息。

### 4.3 数据最小化与留存

- 只收集匹配与申请必需的信息。
- 定义数据留存期限；到期或注销后安全删除（含物理文件）。

### 4.4 审计留痕

- 敏感操作记录 `sa_audit_logs`：谁、何时、对什么、从哪个 IP、做了什么。
- 重点：资料**查看 / 下载**、审核、权限变更、批量导出。

## 5. 传输与基础加固

| 项 | 措施 |
|----|------|
| 传输加密 | 全站强制 HTTPS，后台强制 SSL |
| 基础加固 | 复用仓库 `mu-plugins/security-hardening.php`（版本隐藏、XML-RPC 禁用、用户枚举防护、安全头、登录限制等） |
| 登录安全 | 登录尝试限制、强密码策略、（可选）二次验证 |
| 文件上传 | 类型白名单、大小限制、内容嗅探校验、禁止可执行文件 |
| 安全头 | X-Frame-Options / X-Content-Type-Options / Referrer-Policy / CSP（按需） |
| 会话 | 安全 Cookie（HttpOnly/Secure/SameSite） |
| 后台 | 禁用文件编辑器（`DISALLOW_FILE_EDIT`），限制后台访问 |

---

## 6. 上传文件安全校验细则

```
1. 扩展名白名单：pdf, jpg, jpeg, png（按资料类型定制）
2. MIME 类型校验（真实内容嗅探，不只信扩展名）
3. 大小限制（按类型，如 ≤ 10MB）
4. 文件名清洗/随机化，杜绝路径穿越
5. 图片可选二次处理（去除 EXIF / 重新编码）以剥离潜在恶意负载
6. 拒绝 .php / .phtml / .html 等可执行/脚本类型
```

---

## 7. 通知/邮件安全

- 密码找回、验证链接使用一次性、带时效的安全令牌。
- 邮件不含敏感信息明文（如不在邮件正文放资料内容）。
- 防枚举：找回密码提示统一化，不泄露账号是否存在。

## 8. 部署与运维安全

| 项 | 措施 |
|----|------|
| 配置 | 沿用 `config/wp-config-sample.php`（非默认前缀、密钥、生产关调试） |
| 上线检查 | 运行 `scripts/security-check.sh` |
| 备份 | `scripts/backup.sh`；备份含加密附件与密钥的**分离存储与保护** |
| 权限 | 文件系统权限最小化；受保护目录不可被 Web 列目录 |
| 日志 | 保留访问/错误日志，定期审查 |
| 更新 | WP 核心/插件及时更新 |

---

## 9. 威胁与对策速查

| 威胁 | 对策 |
|------|------|
| 附件被直连下载 | 受保护目录 + 禁直连 + PHP 鉴权端点 |
| 附件泄露（拖库） | 加密存储 + 密钥分离 |
| 顾问越权看他人学生 | Access Guard 按 assignments 强制校验 |
| SQL 注入 | `$wpdb->prepare()` 全覆盖 |
| XSS | 输出转义 |
| CSRF | WP Nonce |
| 恶意文件上传 | 白名单 + 嗅探 + 随机名 + 禁可执行 |
| 暴力登录 | 登录限制（沿用加固插件） |
| 合规缺失 | 同意书 + 删除权 + 审计日志 |
